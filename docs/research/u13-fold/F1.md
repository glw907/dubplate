# F1: TagProbe: build the beets matcher probe and wire it into production serve

Each finding below is confirmed by an adversarial verifier (or by the conductor directly). Fold every one. Severity blocker findings are non-negotiable; majors may be adapted if the fix text conflicts with the code, but the defect must end up fixed.

## F1.1 [blocker] Production serve never wires TagProbe: no main-lane upload can ever reach the library, and every one leaks its staged directory forever

File: /var/home/glw907/Projects/dubplate/internal/serve/serve.go:132

`Options.TagProbe` is documented as "production wiring of the real probe is cmd/dubplate/serve.go's job" (/var/home/glw907/Projects/dubplate/internal/serve/upload.go:176-179). It is not wired. `NewServer` builds the Engine with `Options{Now, OnPromoted, TusBasePath}` only (/var/home/glw907/Projects/dubplate/internal/serve/serve.go:132-136), and `runServe` passes no probe either (/var/home/glw907/Projects/dubplate/cmd/dubplate/serve.go:43-47). `NewEngine` therefore installs `unavailableTagProbe`, which always returns `ErrTagProbeUnavailable` (upload.go:212-213, 123-125).

Concrete outcome for a family member on the deployed box: they upload a perfectly good FLAC album to the default collection, the format gate passes, `completeSession` takes the `err != nil` branch (upload.go:651-655), sets `ProbeUnavailable`, and returns. `promoteInto` is never called, so nothing is renamed into the inbox and the importer never sees it. The page shows the honest "retry later" state forever, because there is no retry: every subsequent attempt hits the same hardcoded failure. Only a session created against the exact `privateCollection` string bypasses the probe (upload.go:642-646) — and on the running dev instance that collection is not even in the configured collection list, so that escape hatch is closed too (see the separate private-lane finding).

Second-order damage: a `ProbeUnavailable` session is marked `completed` and its staged directory is deliberately left under UploadsDir ("leaves the session staged and unpromoted rather than discarding it", upload.go:620-624). `Store.expired` only returns sessions where `!completed` (session.go:330-334), so the sweep will never reclaim it and nothing else on the box does. Every main-lane upload permanently consumes disk until `archive.FreeSpace` drops under `FreeFloorGB` (5 GiB default) and `preCreate` starts rejecting everything with `ReasonNoSpace`.

Proposed fix: Wire the real U8 beets-matcher PROBE into `NewServerDeps`/`Options.TagProbe` before this ships, and make `NewServer` refuse to start when it is nil rather than silently falling back to `unavailableTagProbe` — a fail-closed default is right for a unit test, wrong for a composition root. Separately, give `ProbeUnavailable` and `PushedBack` sessions a real reclamation path (see the sweep findings).

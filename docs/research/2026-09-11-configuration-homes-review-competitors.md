# Configuration homes spec: competitor capabilities and user demand review

Adversarial review record, 2026-09-11, fresh-context `claude-opus-5` reviewer against
`docs/specs/2026-09-11-configuration-homes-design.md` revision 2. Findings are folded
into revision 3 of the spec; this file is the citation record. Reviewer output verbatim below.

---

I read the spec, the 2.0 hooks, and surveyed the field. Findings below, ranked.

---

## 1. Weaker than a competitor, or ignoring demonstrated demand

**F1 — CRITICAL. A collection has a writer and an owner but no *reader*.** §"Collections carry their shape" defines exactly two attributes of control, and §"Attaching a local library" has Mirror "publish the local collection to the server" with no statement of who can then see it. Every comparable product has a visibility axis as a first-class column: Navidrome 0.58 multi-library gates access per user (admins get all libraries, regular users must be granted each one — https://www.navidrome.org/docs/usage/features/multi-library/); Jellyfin's "Enable access to all libraries" toggles into per-library grants (https://jellyfin.org/docs/general/server/users/adding-managing-users/); Ampache has `catalog_filter` per user (https://github.com/ampache/ampache/wiki/catalog-filters); Funkwhale makes it the defining property — private / local-instance / public per library (https://docs.funkwhale.audio/user/libraries/index.html). The demand is documented: Navidrome discussion #2452 is a parent asking that children's music not be mixed into his collection (https://github.com/navidrome/navidrome/discussions/2452), and #748 asks to expose only a subset (https://github.com/navidrome/navidrome/issues/748). **Change:** add `visibility` beside `writer` and `owner` on the collection row (owner-only / group / shared-link), plus an explicit per-member grant set for the non-default case; route to rung 6 with hook 8, since retrofitting a reader axis after collections exist is a schema and projector rewrite.

**F2 — HIGH. Member preferences carry no entitlements, and quotas live only in the global settings table.** §"The rule" lists preferences as default collection, notifications, starred, playlists, queue; §"The server's own knobs" puts "intake limits: upload size, concurrency, quotas" in the global table. Funkwhale's quota is a global default explicitly overridable per user (https://docs.funkwhale.audio/user/accounts/quota.html); Ampache 7 added per-user upload catalogs, replacing the single global preference (https://ampache.org/docs/help/upload-catalogs/); Jellyfin and Plex both carry per-user bitrate/download entitlements. Without this, an admin's only lever against one member filling the disk is a global limit that punishes everyone. **Change:** a per-member override row (quota, upload allowed, may-create-collections, max concurrency, collection grants) with stated precedence: admin bound ≥ member override ≥ settings default.

**F3 — HIGH. No sharing verb, and no home reserved for one.** Navidrome shipped public shares after #1029 (https://www.navidrome.org/docs/usage/features/sharing/); Plex's entire social model is sharing libraries outside the household. The spec's world contains only roster members. **Change:** either decline sharing explicitly with a reason, or file the home now (share rows in the store, keyed to item and expiry — never a settings key) as a 2.0 forward hook. This is the same schema decision as F1; deciding them apart is how you get two incompatible ACLs.

**F4 — MEDIUM-HIGH. Retiring or handing over a collection has no stated effect on other members' per-member rows.** §"Collections carry their shape" gives the admin retire and reassign-owner; the 2.0 spec specifies cascade for catalog removal, but nothing here says what happens to a second member's playlist entries, starred rows, or saved queue when a collection they did not own goes away or changes visibility. Jellyfin #7071 is the cautionary case: playlists modeled beside the permission system, not inside it, produce an infinite spinner and an all-or-nothing workaround (https://github.com/jellyfin/jellyfin/issues/7071). **Change:** state the cascade in this spec and route it to rung 6 beside hook 5.

**F5 — MEDIUM. Mirror manufactures duplicates with no collapse surface.** §"Attaching a local library": Contribute refuses duplicates by hash or MBID, Mirror deliberately creates the same album in two collections. Four members mirroring a shared taste yields four visible copies. Plex merges duplicate matches by default and users still file about the consequences (https://forums.plex.tv/t/duplicate-song-handling/925527); Navidrome's own doc concedes artists spread across libraries with no dedupe. **Change:** a member preference "collapse duplicate albums across visible collections", keyed on content hash / release MBID, and a per-collection flag for whether it participates in the merged group view. Name it now so the rung 6 projector carries the key.

## 2. Conflicts with the Plex/Spotify family expectation

**F6 — HIGH. "Any member may create server collections by default, since a group of family or friends is the product's shape" (§Collections) inverts what a family plan means to users.** Apple Music Family: "each person's Music Library and Playlists are entirely independent" (https://discussions.apple.com/thread/254595265). Spotify Premium Family: every member gets their own account, own library, own Wrapped (https://www.spotify.com/us/family/). The shared thing is the *entitlement*, not the library. dubplate's default makes every member-created collection group-visible by construction, so a member's first act of self-expression is public. **Change:** member-created collections default to owner-private with an explicit "publish to the group" action; admin-owned collections stay group-visible. The product framing survives intact and the default stops surprising people.

**F7 — MEDIUM. Theme as a machine setting is the wrong answer from a right-looking test.** §"The rule" sells "a different theme on each [machine]" as a feature, and §"Two surfaces" derives it from "does the server's behavior change". Roon profiles follow the person across every endpoint (https://kb.roonlabs.com/Profiles); Navidrome, Plex and Jellyfin all store theme/language per user server-side. Nobody asks for a different theme per laptop; people ask why their theme did not follow them. **Change:** add a second clause to the test — a knob that expresses the *person* rather than the *hardware* is a member preference even when the server's behavior does not change. Theme, language, and ReplayGain mode move to preferences; audio device, keybindings, server URL, token, and source folders stay machine.

**F8 — MEDIUM. There is no "my library" view over a shared collection, so owning a collection is the only personal shelf.** Roon's answer to "different library per user" is profiles plus favorites over one library, explicitly refusing per-user libraries (https://community.roonlabs.com/t/different-library-content-per-user/31394); Navidrome's maintainer offered favorites as the workaround in #2452. The spec's only mechanism duplicates rows and files. **Change:** state in §Collections that the personal shelf is starred/library-add over group collections, and that a per-member collection is for *contributed content*, not curation — otherwise a later rung "fixes" curation by minting a collection per member.

## 3. Confident claims my research contradicts

**F9 — HIGH. "This is the Lidarr and Sonarr split, where the config file holds only what the process needs to find its database" (§The server's own knobs).** False. `config.xml` also holds port, bind address, URL base, SSL, API key, authentication method, log level, analytics and branch, and the UI writes those settings back into the file, requiring a restart for network changes (https://wiki.servarr.com/sonarr/faq, https://wiki.servarr.com/sonarr/environment-variables). The real *arr line is "what the process needs before it can bind and open the DB", which is what dubplate's bootstrap column actually does. **Change:** fix the sentence; the model is fine, the cited precedent is misdescribed, and an implementer taking the citation literally will move bind address into the store.

**F10 — HIGH. "Subsonic clients offer folder browsing, and in folder mode the layout template is the user interface" (§Shape bounds), presented as the one constraint surviving every driver.** Under the rung 12 reference driver this has been false: Navidrome's `getIndexes`/`getMusicDirectory` returned a synthesized Artist/Album tree rather than disk folders, which is exactly why clients expecting a real hierarchy misbehaved (https://github.com/navidrome/navidrome/issues/5232), and real folder browsing arrived only recently behind a `Subsonic.FolderBrowsing` switch. So the layout template is *not* the interface by default on Navidrome, and the 2.0 built-in streamer derives folders from the projector anyway. **Change:** demote to "may be the interface, per driver and version; rung 12 verifies against the pinned Navidrome build", matching how the spec already treats art filenames and read tags.

**F11 — LOW. "a collection must be a disjoint directory subtree so it can map to a music folder" (§Shape bounds)** is right about Navidrome's roots but implies entity disjointness it does not buy: Navidrome's multi-library doc states artists can have albums and songs spread across libraries. Add half a sentence so rung 12 does not assume per-library entity isolation. (The beets claims in the same section — query-dependent path formats, database-only facts — check out; no change.)

## 4. Three competitor mistakes the spec should decline by name

**D1 — Jellyfin's pseudo-library permissions.** Playlists are a library in Jellyfin's permission model but cannot be granted individually, so a user with partial access cannot open playlists they created themselves (#7071). **Decline:** every per-member object (starred, playlist, queue, history) is keyed to the member and its visibility computed per referenced item at read time, never by granting access to a container.

**D2 — Navidrome's and Jellyfin's "a library is a disk root folder".** It forces an admin, a directory, and often a restart into what should be a member's self-service act, and it is why Navidrome's per-user-library request (#2452) got an answer shaped like folder assignment rather than what users asked for. **Decline:** a dubplate collection is a catalog row whose on-disk location is an implementation detail of its writer. Say so, with the reason, so a driver's subtree constraint is never allowed to redefine the concept.

**D3 — Plex's two-tier account model.** Home managed users, Home members, and outside friends have different and famously confusing capability sets — managed users can only receive shares from the Home admin who is also the server admin (https://support.plex.tv/articles/203948776-managed-users/), and restriction profiles interact oddly with label/rating rules. **Decline:** one roster, one identity kind, one admin flag (already rung 5's shape), with capability differences expressed as per-member overrides (F2), never as account classes. Funkwhale's follow-approval-per-library is the same mistake in federated dress and should be declined in the same sentence: the admin's roster is the trust boundary for a group of friends.

registered key carries a description and a sensitive mark, the network actor keys on `UserID`, and the roster API
retires.

## Conventions every task follows

- **Gate.** `bash scripts/gate.sh` (the full gate) and `bash scripts/gate.sh --scope-changed --base <base>` (the fast
  lane), from the worktree root, with the Bash tool's `timeout: 600000`, re-issued on exit 75 until it prints `gate
  exit:`. A worktree-isolated session's Bash guard refuses the quoted `cairn-run-gate '<string>'` form and accepts the
  wrapper. Never fall back to a bare `bash scripts/check.sh` for an acceptance.
- **The base, and why the fast lane names it.** T0's sweep writes `go.mod`, `go.sum`, `web/package.json`, or
  `web/package-lock.json` when anything moves, and `check.sh` classes each as gate machinery (`check.sh:364-370`),
  which promotes a scoped run to the full form (`:458-459`). Without `--base`, a branch's change set runs from the
  merge base with master, so every later scoped run on this branch would include T0's files and run the full gate.
  Every fast lane on this branch therefore passes `--base <base>`, where `<base>` is the literal 40-hex id of the
  commit the task started from: the session's `HEAD` at task start, written into the clock file as a fourth line
  `base=<sha>` (the clock hook reads only `task=`, `start=`, and `estimate=`), or, for a pair or a single dispatch,
  the dispatch commit. `check.sh` uses a supplied base only when it is a full hex id that resolves to itself and is
  an ancestor of `HEAD`, and otherwise runs the full form, so a wrong value costs time, never coverage. Tasks that
  edit `web/scripts/gates/*` or `web/scripts/rendered/*` (T9 to T11) run the full form by that same rule; that is
  expected. Most Go tasks link the rendered test binary, so their fast lane runs the rendered leg on the heavy lane.
  This departs on purpose from the adapter's "Pass no `--base`" (`dubplate-pass` SKILL.md, "Fast lane"), for the
  reason above; a resumed session keeps it, and the PR's "Found, not done" list carries the adapter amendment.
- **Setup.** `npm ci --prefix web` in the session's worktree, and in each subagent's worktree before its first gate
  (the gate refuses a worktree without `web/node_modules`).
- **Test-first.** Every `auth-data` task writes its acceptance tests first and records each failing at the task's
  start commit, in the PR notes, before the code lands.
- **Mutation proofs are run.** Each task's mutations are applied one at a time, the named test run, and the failure
  recorded in the PR notes with the test name. A mutation that does not fail is a finding against the test, fixed in
  the same task. No mutation is narrated in a comment.
- **Fixture states.** Every proof names the fixture state it needs (populated, selected, renamed, removed), so it
  cannot pass on an empty fixture. A `web/` proof is a named rendered row (`web/scripts/rendered/run.ts` with its Go
  host `cmd/dubplate-server/rendered_test.go`) that says what it intercepts and what it reaches for real: `web/` has
  no component test runner.
- **Layering.** `internal/ops` and `internal/ops/opshttp` import no `internal/auth` or `internal/settings`;
  `internal/auth` and `internal/settings` import no `internal/ops`; `internal/auth` imports no `internal/settings` or
  `internal/config` (it imports neither today); `internal/settings` imports no `internal/notify`. Only
  `internal/ops/admin` and `cmd/dubplate-server` join them. kin-openapi appears only in `_test.go` files under
  `internal/ops/opshttp`; the no-link test (`internal/harness/conform/arch_test.go`, the `github.com/getkin` row)
  stays green.
- **No export ahead of a caller.** Every new export names its production caller in the task that adds it.
- **Config keys** are declared from this pass's own file, `cmd/dubplate-server/api.go`, registered through one
  `newProductionRegistry` line (`cmd/dubplate-server/main.go:99-108`); `internal/config/keys.go`'s rows change only
  for hook 18's descriptions and marks.
- **No migration.** No file under `internal/engine/store/migrations/` changes.
- **Skills.** Go under `go-conventions`, with "idiomatic, architecturally beautiful Go" an acceptance dimension of
  every Go task; `web/` under `svelte-conventions`, `ts-conventions`, the `daisyui` skill, and the visual identity
  spec (`docs/superpowers/specs/2026-09-24-visual-identity-design.md`), which every `web/` task reads. Copy uses plain
  terms: "the group", "a member".
- **Per-task review.** On each `auth-data` task, the session runs `diff-reviewer` at task scope on the task's commit
  (or the merged pair's range) against the task's acceptance. `accept` continues. `fix` gets one fix commit whose
  acceptance quotes each finding verbatim (location, finding, fix), then one re-read. A second `fix`, or any
  `escalate`, is a stop. Each verdict, the re-read's included, appends `review T<n>=<verdict> <sha>` to the PR notes.
- **Commits.** One commit per task, subject starting with the task id (`T3: Add removal and demotion to the
  roster`), imperative mood, specific files only (`git add <path>...`, never `-A`), with the trailer the session's
  system reminder names. A pair half merges with `git merge --no-edit <branch>`.
- **Records.** The PR notes live at `<git dir>/pr-notes.md`, where `<git dir>` is `git rev-parse --absolute-git-dir`
  in the session's worktree: never committed, and they survive a restart. The first line, written right after the
  planning-branch merge, is `launch-base=<sha>`. Before each dispatch the session appends `dispatch T<a>[+T<b>]
  sha=<40-hex>`. Each task appends its test-first failures, its mutation results, its review line, and anything found
  outside its scope. A subagent writes nothing outside its worktree and returns its records in its final report, with
  its worktree path and branch; the session appends them. The session writes with the Write tool or one plain command
  per write.
- **Clock.** At each task start the session writes `pass-task-clock` in its worktree's git dir with `task=<id>`,
  `start=<epoch>`, `estimate=<minutes>`, and `base=<sha>`, and removes it at the task's end. For a pair or a single
  dispatch it writes one file (`task=T1+T2`, the larger estimate, the dispatch commit as `base`) before dispatch,
  checks the overrun when the dispatch returns, then removes it. Subagent worktrees hold no clock file.
- **Dispatches.** A pair is two Agent-tool subagents, `subagent_type: "general-purpose"`, `isolation: "worktree"`,
  effort `medium`, dispatched after the session commits, so `worktree.baseRef: "head"` branches them from that
  commit. T3 and T5 run on `opus` (novel correctness-critical logic the spec leaves to the implementer: the epoch
  ordering and the guard's transaction, the gate's decision point and the notice's ordering); every other dispatch
  runs on `sonnet`. T5 is a single dispatch the session waits on. The dispatch names the commit's full id; the
  subagent's first act is `git merge-base --is-ancestor <dispatch sha> HEAD`, and a failure is a stop. Each gets its
  task's full text, the "Decisions this plan takes", "Behaviors this plan relies on", and "States" sections, and this
  section, all verbatim, plus the spec's path with the instruction to read every spec section and AC its task cites
  before writing tests; commits; never pushes; and skips agent-memory maintenance. The session merges, runs the fast
  lane with `--base <dispatch sha>`, runs the per-task review, and pushes.
- **Stops.** A red the session cannot fix in two attempts, a merge conflict, a clock stop, an auto-mode classifier
  refusal, a per-task review stop, or a finding that would change the approved design: write `docs/STATUS.md` on the
  branch (task in flight, what failed, one question with a recommendation), commit and push it, run `notify-send -u
  normal "admin-api-1: stopped"`, and wait. Never work around a refusal with another tool. A subagent whose gate is
  not green after two attempts returns its work uncommitted, and the session applies this rule before merging.
- **Resume.** After a crash, an API drop, or a restart, the session (the same one, or a fresh one launched with the
  same prompt, which enters the existing worktree with EnterWorktree's `path`; a `worktree-admin-api-1` branch with
  no worktree directory is a stop, per the prompt's first check) first rewrites the clock file's `start=` to now. If
  the PR notes carry no `launch-base` line, it checks `git merge-base --is-ancestor worktree-admin-api-1-plan HEAD`,
  merges the planning branch if that fails, and finishes the prompt's launch steps. It reads this pass's task
  commits with `git fetch origin`, then `git log --no-merges --format='%h %s' <launch base>..HEAD ^origin/master`,
  where `<launch base>` is the PR notes' first line. Only the last `dispatch` line in the PR notes can be unsettled,
  since the session merges and reviews each dispatch before the next. For that line it lists the candidate branches with `git worktree list --porcelain` (each entry's `branch refs/heads/...` line), drops its
  own branch `worktree-admin-api-1` (which sits at the dispatch sha), and keeps those where `git merge-base
  --is-ancestor <dispatch sha> <branch>` holds. Each candidate is one of three:
  - it carries its `T<n>:` commit (`git log --format=%s <dispatch sha>..<branch>`) and is an ancestor of `HEAD`:
    merged, done;
  - it carries its `T<n>:` commit and is not an ancestor of `HEAD`: merge it now, run the fast lane with `--base
    <dispatch sha>`, run the per-task review, and push;
  - it has no `T<n>:` commit: a stop, since its worktree may hold warm uncommitted work, unless the same session can
    resume that subagent with `SendMessage`.

  A committed `auth-data` task with no `review T<n>=` line (and T6 with no `security-read=` line) is the task in
  flight, at its review step. Otherwise the session resumes at the first task whose acceptance fails and never
  re-applies a committed task.
- **Scope.** A defect found outside a task goes to the PR body's "Found, not done" list.

## Decisions this plan takes

The spec leaves these to the plan. Each is method or architecture, decided on its evidence; P1 to P11 carry the old
plan's decisions, re-read at `551bf4f`, less its member-cap clauses.

- **P1. The contract document's path** is `internal/ops/opshttp/openapi.yaml`, beside the tests that load it. Nothing
  embeds or serves it.
- **P2. The mount and the context carrier.** `opshttp` exports one constructor for the mount; its first caller is
  `cmd/dubplate-server/api.go`. The mount takes the job seam, the admin seam, the prefix, a logger, and a verifier
  function `(http.ResponseWriter, *http.Request) -> (ops.Actor, ops.Privilege, error)`. It cuts `<prefix>/api/v1/`
  itself (branching on `strings.CutPrefix`'s `found`), answers every other `api` path with JSON `not_found`, then
  calls the verifier: an error wrapping a new `unauthenticated` sentinel answers 401, and any other error answers 500
  `internal`. An admitted caller rides the request context under an unexported key type, and `opshttp`'s authorizer
  is its only reader. The verifier is built in `api.go` from a new session check in `internal/auth`, which verifies
  through the seam, refreshes on a same-origin request as `RequireAdmin` does (`internal/auth/admin.go:110-133`), and
  reports a refused session apart from a server failure. The verifier builds the actor from `Session.AnchoredAt`,
  never `IssuedAt`.
- **P3. The 401 and 500 split.** A verification refusal whose cause is in `gateRefusals` (`admin.go:142-150`: no
  cookie, a malformed or forged session, the cap, expiry, revocation, an unknown member) answers 401
  `unauthenticated`. A failed setting read or roster lookup is the server failing: 500 `internal`, logged at Error, as
  `gateRefusalReason` already classes it (`:155-165`).
- **P4. The admin settings route** is `server-settings`, a single segment (`Shell.Register` refuses a separator,
  `internal/serve/serve.go:120-121`), behind `RequireAdmin`, with a `no-store` document row beside `members`
  (`cmd/dubplate-server/web.go:104-108`). The page title is "Server settings". AC20 keeps the route off `settings`,
  which it leaves to the member preferences page. The page is reached from one link on the members page, which is
  already admin-only. A header entry would show to every member, since a static page cannot tell an admin from a
  member, and the non-admin rendered row asserts the header carries no admin link (`web/scripts/rendered/run.ts`,
  `membersLinkPresent`, near `:3706-3710`); the members-page link needs no role detection.
- **P5. How the admin returns after a fresh sign-in.** The link interstitial's `signed_in` state offers no onward
  link, by design (`web/src/routes/login/link/+page.svelte:15-17`). The pages add no return parameter, which would
  add a redirect target to validate. On `reauthentication_required` a page keeps the pending change, and its sign-in
  link opens the sign-in page in a new tab (`target="_blank" rel="noopener"`), so the change survives in the first.
  The page offers a retry, which the cookie set in the other tab serves. The copy says to sign in from this browser.
- **P6. The re-authentication window** is `DUBPLATE_REAUTH_WINDOW`: a duration setting, store-homed, sensitive, apply
  mode next-operation, default `2h` (GitHub sudo mode's window, spec D10's source), floor `5m` (the anchor is set when
  the link is consumed, `internal/auth/session.go:80-86`, so the round trip that matters runs from that click to the
  retry), ceiling `24h`. A correlated rule, registered as `sessionLifetimeWithinCap` is
  (`cmd/dubplate-server/auth.go:325`), refuses a window at or above `DUBPLATE_SESSION_ABSOLUTE_CAP`. It is strict:
  `durationAtLeast` admits equality (`auth.go:272`), so the rule is not that helper reused as is.
- **P7. Wire names.** A member is `user_id`, 32 lowercase hex characters. The `error.detail` enumeration is exactly
  ten values: `additionOutcome`'s seven refusals (`internal/auth/admin.go:312-337`: `duplicate_address`,
  `duplicate_username`, `invalid_address`, `invalid_display_name`, `blank_display_name`, `invalid_username`,
  `missing_username`; the spec keeps each add outcome's name, spec:95-96) plus `last_admin`, `environment_sets`, and
  `busy` (spec fold V5). `duplicate_principal`, which no Go code returns, is not one. `admin_not_grantable` and
  `unknown_field` leave it, since a decoder that ignores unknown keys gives neither a cause
  (`internal/ops/opshttp/opshttp.go:141-144`). The values are exported constants of one shape, `Detail<Name> =
  "<value>"`, declared together in one `internal/ops` file, which T6's parity test and T9's deck gate parse.
- **P8. doctor's `DUBPLATE_ADMIN_EMAIL` warning has two messages, not three** (the spec fold's over-ceremony item 2).
  A removed member and an address no member holds name one action: `member add <address> --admin`, or point the
  variable at a live admin (`addUser` reactivates a tombstoned row with the flag, `internal/auth/roster.go:395-419`). A
  live non-admin names another: no promote verb exists and `member add` refuses a live address, so the only action is
  to point the variable at a live admin. All three states warn (AC21). A warning is the row's status text with
  `failed` false, as the members row's advisory status already is (`cmd/dubplate-server/doctor.go`,
  `membersRowStatus`); doctor gains no row state.
- **P9. The roster's in-write admin check is one exported roster function over a `*store.Tx`.** The settings write
  functions take it as a guard parameter of type `func(context.Context, *store.Tx) error` from `internal/ops/admin`,
  which closes over the actor's `UserID`, so the users table's SQL stays in `internal/auth` and `internal/settings`
  imports no `internal/auth`. T3 and T4 build the two sides to that one shape. The command line passes no guard.
  The roster's refusals the seam maps (`errMemberNotFound`, `errNoAdmin`, `errActorNotAdmin`, and the seven add
  refusals behind P7's details, `internal/auth/roster.go:39-105`) are unexported today; T3 exports them as sentinels
  for `internal/ops/admin`'s `errors.Is`, its production caller in T5.
- **P10. The roster's write dependencies reach only the write paths.** The epoch store and a clock reach the add,
  remove, and demote paths; `member list` and every read build no epoch store and open no auth leaf.
- **P11. `user_id` parsing** accepts exactly 32 characters that equal their own lowercase hex re-encoding. The empty
  string and the all-zero id (the `UserID` zero value, "never resolved", `internal/identity/identity.go:205-208`)
  answer `invalid_request`.
- **P12. The member cap leaves this pass, to `admin-api-2`.** The old plan took PS's member cap into 14a as a "spec
  deviation" (old plan `:239-249`). The approved spec does not include it, and adding a ratified 0.8 mechanism beyond
  an approved design is scope pass-core says a grant never authorizes. The cap is separable at no cost: PS puts it in
  one function, the roster's add path, which every channel calls (PS:137-139), so it lands on both add channels
  whichever pass adds it; the old plan itself named it a clean split seam (`:129-131`). PS routes it to "Rung 14
  settings" (PS:580), and `admin-api-2` is rung 14's second pass, which lands before `cutover`; nothing is live in the
  meantime. It goes to BACKLOG #74, tagged `#rung:admin-api`, with its PS:145-147 reconciliation (this pass's notice
  rule sends no command-line notice, and no command-line set verb exists). So the PS member-cap note and its erratum
  are dropped from this plan; the pass that builds the cap edits PS in place.

## Behaviors this plan relies on, quoted

The spec's quotes stand (spec, "Planning-miss prevention", first bullet). Added, read 2026-10-10 by the old plan and
re-checked at `551bf4f` where a line is cited:

- `go doc encoding/hex.DecodeString`: "DecodeString expects that src contains only hexadecimal characters and that
  src has even length." It accepts uppercase (`hex.DecodeString("ABCD")` returns `[171 205] <nil>`) and returns an
  empty slice and nil for `""`, so P11's length check is separate from the re-encoding check.
- `go doc strings.CutPrefix`: "If s doesn't start with prefix, CutPrefix returns s, false."
- `go doc context.WithValue`: "The provided key must be comparable and should not be of type string or any other
  built-in type to avoid collisions between packages using context. Users of WithValue should define their own types
  for keys."
- `internal/auth/session.go:76-86`: `IssuedAt` "is when the session was last issued ... A refresh moves it";
  `AnchoredAt` "is the session's original issue time ... every check that must reason about when the session was born
  reads the anchor rather than IssuedAt, which a refresh advances."
- `go doc ./internal/engine/store Handle.Update`: "Update runs fn inside one IMMEDIATE transaction ... ctx must carry
  a deadline, which bounds the wait for the write pool's one connection inside this process. The wait on another
  process's write lock is bounded by the busy timeout alone: a deadline shorter than the busy timeout does not
  shorten it." `internal/engine/store/write_test.go:588-590` records it measured: "SQLite's busy handler does not
  stop for the driver's interrupt, so a deadline shorter than the busy timeout still waits the full busy timeout on
  another process's write lock." So the same handle's held write connection under a short deadline answers
  `context.DeadlineExceeded` (`:573-585`), and a second handle's open transaction answers `ErrBusy` (`:591-606`).
  AC16's concurrency proof and both arms of the `busy` detail rest on it.
- `internal/engine/store/conn.go:34-36`: "ErrBusy wraps a failure after which SQLite's write lock stayed held past
  the busy timeout." The roster API's `additionOutcome` already maps it and `context.DeadlineExceeded` to busy
  (`internal/auth/admin.go:304-311`).
- `internal/settings/accessor.go:20-21`: "A setting read before a write enters [store.Handle.Update] is the value in
  force for that operation; read it outside the callback." The window read follows it.
- `internal/auth/store.go:49-58`: `Open` "creates the leaf and both record subdirectories under stateDir if they do
  not already exist" and "refuses to start when the leaf itself already has a mode wider than dirPerm".
- `cmd/dubplate-server/auth.go:272-291`: `durationAtLeast` refuses only when `l < s`, so it admits equality.
- `go doc github.com/getkin/kin-openapi/openapi3filter Options`: "Set IncludeResponseStatus so ValidateResponse fails
  on response status not defined in OpenAPI spec."
- `internal/notify/notify.go:80-89`: `Send` "reports failure to its caller and makes no retry or best-effort policy

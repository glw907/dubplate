3. **`tagio` does not depend on `internal/engine/matcher`.** `tagio`

6. **The PADDING reservation is 8 KiB**, against mutagen's 1 KiB. A
   measured fifteen-field write already produced a 575-byte
   VORBIS_COMMENT block (`INV:407-427`), and a full 69-key set with
   MusicBrainz ids and credit lists runs well past a kilobyte. A
   reservation too small to absorb a retag makes the optimization dead
   on arrival.
7. **The writer preserves unknown metadata blocks unconditionally.**
   APPLICATION, SEEKTABLE, CUESHEET, and reserved types are copied
   through by declared length, under re-emitted headers. This is the
   shadow reader's existing behavior and the format's expectation.
   PADDING is the one exception and is not preserved: every incoming
   PADDING block is dropped and one 8 KiB block is written last, so a
   file retagged N times carries the same padding as one retagged once.
   Comments the tag set does not own are preserved too, which the
   contract section states as behavior.
8. **The frame region is the content hash's extent.** `S2`'s forward
   hook 1 puts a content hash on the catalog row, computed at rung 7's
   gate (`S2:359-360`). A tag rewrite changes the file's bytes and
   leaves the audio frame region's bytes alone, because a tag write
   moves no audio sample and STREAMINFO's MD5 covers unencoded audio
   (RFC 9639 section 8.2). A whole-file hash goes stale the first time
   rung 9's retag verb runs; a frame-region hash survives every retag
   the library ever takes. Rung 8 exposes the offsets its parse already
   computes, so rung 6's schema and rung 9's retag verb agree on one
   answer. The cost is that the hash no longer detects a tag-only edit
   made outside the server, which a separate tag-region digest can cover
   later if anyone wants it.
9. **The writer refuses a container it did not fully understand.** More
   than one VORBIS_COMMENT block, a STREAMINFO that is not first, a
   block appearing after a header whose last-block flag is set, or a
   declared length running past the end is an error and never a
   best-effort write. RFC 9639 sections 8.1, 8.2, 8.5, and 8.6 make each
   one a spec violation rather than an edge case. The refusals apply to
   the reader too, so the adopter consequence and the capture-path
   effect are stated under "What rung 8 needs from earlier rungs".
10. **Field names and values follow RFC 9639 section 8.6 and beets
    together.** An invalid field name is rejected. Invalid UTF-8 in a
    comment is replaced with U+FFFD per code point on read, matching
    mutagen's `errors='replace'` (`mutagen/flac.py:352`,
    `mutagen/_vorbis.py:109`), and values are valid UTF-8 by
    construction on write. Revision 1 said errors were ignored the way
    `safe_cast` does; that branch fires only for a `bytes` value
    (`mediafile/utils/type_conversion.py:21-22`) and never in the
    oracle's path, where beets item values are `str`.
11. **`internal/atomicfile` grows the streaming write in pass 8a**, as

12. **The streaming write fsyncs the containing directory.**

13. **Rung 8 declares no configuration key**, stated in those words.

## The write side of beets, as a contract

INV sections 1 and 2 are the close read. What follows is the part a Go
writer has to satisfy, stated as behavior.

**The mapping lives in two class variables, not in a function.** There
is no module-level `apply_metadata` in beets 2.13.1. There are
`AlbumMatch.apply_metadata` and `TrackMatch.apply_metadata`, plus
`TrackInfo.merge_with_album`, and the album-to-item renaming happens in
`AlbumInfo.MEDIA_FIELD_MAP` and `TrackInfo.MEDIA_FIELD_MAP`
(`INV:54-127`). Rung 8 consumes the result of that mapping rather than
reproducing it: the corpus froze it into `Expected.AppliedFields` at
rung 2, and the conformance instrument reads those values.

**The writable set is 69 keys**, the intersection of
`Item._media_fields` with `MediaFile.sorted_fields()`, computed against
the pinned venv and matching the corpus handoff key for key
(`INV:159-172`). The nine read-only audio properties are never a
writer's target.

**Four input states, and the Go type is where they are chosen.**
`MediaFile.update` deletes on `None` and sets on everything else. A null
removes the key and reads back as `None`. A string field's empty value
writes a comment with an empty value. A list field's empty value writes
no comment at all, because `ListStorageStyle.set_list` stores an empty
value list and mutagen emits nothing
(`mediafile/storage/base.py:189-200`); measured, `arrangers=[]` and
`genres=[]` produce no `ARRANGER` and no `GENRE` comment and read back
as `None`, so an empty list is indistinguishable on read-back from
absent. A non-empty value is the fourth. Revision 1 stated three states
and folded the two empty forms together. The scale is why it matters:
row 0 of the ledger carries ten nulls and ten empty strings
(`INV:387-403`), and across the twelve subjects' applied fields 45 cells
are `[]` against 149 empty strings. A writer that treats empty and
absent alike fails twenty keys on row 0 alone while every non-empty
value matches, which is the failure mode most likely to look like a
small bug and be a large one.

**Read-back takes the LAST applicable style when nothing is truthy.**
`MediaField.__get__` overwrites `out` on each style and breaks only on a
truthy value (`mediafile/fields.py:48-54`), so a field whose trailing
styles are read-only returns `None` for an empty value even though the
writer emitted an empty comment. Two of the 69 are shaped that way.
`catalognum` has a writable `CATALOGNUMBER` behind read-only `CATALOGID`
and `DISCOGS_CATALOG` (`mediafile/__init__.py:604-606`), and `barcode`
has a writable `BARCODE` behind read-only `UPC`, `EAN/UPN`, `EAN`, and
`UPN` (`:616-620`). Measured on a scratch copy of the committed
template: `catalognum=""` and `barcode=""` put `CATALOGNUMBER=` and
`BARCODE=` on disk and read back as `None`, while `asin=""` (one style)
and `albumartist=""` (three writable styles) both read back as `""`. The
committed ledger already records it, with `catalognum` applied `""` and
recorded null on 5 of 12 subjects and `barcode` on 6 of 12. The
instrument's read-back projection implements the last-style rule, and
both fields carry their own unit test under ruling 1.

**A set writes every applicable style.** Reading takes the first style
whose value is truthy; writing writes every applicable style that is not
read-only. So `albumartist` writes `ALBUM ARTIST`, `ALBUM_ARTIST`, and
`ALBUMARTIST`; `disctotal` and `tracktotal` each write three keys;
`track`, `disc`, `comments`, `label`, `albumstatus`, and `encoder` each
write two. Deleting a field also deletes its read-only styles, so
removing `barcode` removes `UPC`, `EAN/UPN`, `EAN`, and `UPN`
(`INV:230-240`). The conformance instrument cannot grade this rule,
which is why it carries its own byte-level proof; see "What the writer
guarantees".

**A write replaces only the keys the tag set owns.** Every other comment
in the VORBIS_COMMENT block survives untouched and in its original
order. `MediaFile.update` touches only the fields present in its dict
(`mediafile/__init__.py:365-378`), and `VCommentDict.__setitem__`
deletes only the case-insensitive matches of the key being written
before appending (`mutagen/_vorbis.py:275-297`). Measured: a template
copy carrying `COPYRIGHT` and `ORGANIZATION` still carried both after a
mediafile write of `title`. `copyright` is a MediaFile field
(`__init__.py:519`) and is not one of the 69, so beets never touches it,
and a real upload carrying a tagger-specific key keeps it through a
beets write. A writer that rebuilds the block from the 69-key value
model drops all of them, on admit and on every rung 9 retag. Key names
match case-insensitively, per RFC 9639 section 8.6.

Serialization is exact. A float with a string target formats to
`float_places` decimals, which is 2 by default and 6 on both ReplayGain
peaks. A bool becomes `"1"` or `"0"`. A suffix appends after
formatting, and `" dB"` on the two ReplayGain gain fields is the only
suffix in the FLAC table. The R128 pair shifts by Q8, so
`r128_track_gain = -1.5` writes `R128_TRACK_GAIN=-384` (`INV:242-296`).

A multi-valued field repeats its key. `ARTISTS=X` followed by
`ARTISTS=Y` is how a two-element list serializes, and a single-valued
field that reaches a list-backed key writes a one-element list.

**Dates decompose, and the year is zero-padded to four digits.**
`_set_date_tuple` formats the year as `f"{int(year):04d}"` and the month
and day as `:02d` (`mediafile/fields.py:182-201`). The value is `YYYY`,
then `-MM` when the month is truthy, then `-DD` only when the month and
the day are both truthy. `DATE` also writes a bare-year `YEAR` fallback,
unpadded, because that style serializes the int through `str()`
(`mediafile/storage/base.py:109-123`); `ORIGINALDATE` has no fallback.
Only a `None` year deletes the field and its fallback together. A zero
year is written rather than deleted, and a fresh beets `Item` defaults
year, month, and day to the integer 0, so the unknown-date path is the
common production path once rung 9 writes tags. Measured: an update with
every date component 0 wrote `DATE=0000`, `YEAR=0`, and
`ORIGINALDATE=0000`, and read back year 0 with month and day `None`. A
year of 2001 with a zero month and day produces `DATE=2001` and
`YEAR=2001`, and reads back as year 2001 with a `None` month and day
rather than zeros (`INV:277-290`). No subject has a zero year; the
twelve run from 1975 to 2025, so the zero-year and sub-1000-year cases
are ruling 1 unit tests rather than conformance rows.

**Three field pairs collide on one Vorbis key, and iteration order
decides the winner.** `albumtype` and `albumtypes` both write
`RELEASETYPE` and `MUSICBRAINZ_ALBUMTYPE`; `mb_artistid` and
`mb_artistids` both write `MUSICBRAINZ_ARTISTID`; `mb_albumartistid`
and `mb_albumartistids` both write `MUSICBRAINZ_ALBUMARTISTID`.
`MediaFile.update` iterates `sorted_fields()` lexicographically, the
plural sorts last, and the plural wins (`INV:297-308`). **A Go writer
that iterates a map is non-deterministic on three keys.** The tag set
type's write order is therefore part of its contract, not an
implementation detail.

INV's 69-key table (`INV:315-385`) is the row-by-row source, with a
mediafile line citation per row. The plan's first task reproduces it in
the code as the mapping's own citation block, in the shape
`flac.go:209-228` already uses for eighteen rows.

## The container contract

Citations are to RFC 9639, read from the published RFC (`INV:715-806`).

**Layout.** The `fLaC` marker, then the metadata blocks, then the audio
frames (section 6).

**Header.** Four bytes: a last-block flag bit, a seven-bit type, and a
three-byte big-endian length excluding the header (section 8.1). The
asymmetry that catches implementers is that the header length is
big-endian while the VORBIS_COMMENT body's lengths are little-endian.
The flag is the writer's responsibility. A writer re-emits every block
header rather than copying one through, clears the flag on all but the
final block, and sets it on the block it writes last. A
parser rejects any block appearing after a header whose flag is set,
which is one of ruling 9's refusals.

**Blocks.** 0 STREAMINFO, 1 PADDING, 2 APPLICATION, 3 SEEKTABLE, 4
VORBIS_COMMENT, 5 CUESHEET, 6 PICTURE, 7 through 126 reserved, 127
forbidden.

**STREAMINFO** must be present, must be first, and must not appear
twice (section 8.2). Its MD5 covers unencoded audio.

**VORBIS_COMMENT** must not appear twice (section 8.6). Its body is a
little-endian vendor length, the vendor string, a comment count, then
the comments. Its field names are restricted to U+0020 through U+007E
excluding U+003D, and field name evaluation is case-insensitive
(section 8.6). Repeating a field name is legal, which is what makes
multi-value serialization work. FLAC's version carries no framing bit.

**The vendor string is part of the block and part of the type.** The
oracle writes one: measured, a mediafile write into a scratch template
copy produced a block whose vendor is `Mutagen 1.48.1`
(`mutagen/_vorbis.py:73` sets the default, `:185-187` writes it), and a
rewrite of a file that already has a block preserves the loaded vendor
(`:104`). `tagio` reads the vendor, preserves it on rewrite, and writes
`dubplate <module version>` when it creates the block fresh. A container
type that does not carry the vendor cannot round-trip it, so the parsed
block carries it and the round-trip test asserts it.

**The oracle's field-name bound is one code point stricter than the
RFC's.** mutagen's `is_valid_key` accepts 0x20 through 0x7D excluding
`=` (`mutagen/_vorbis.py:25-41`), so U+007E is RFC-legal and mutagen-
invalid. `VComment.load` silently skips a comment whose key fails that
test (`:127-128`) while `validate` raises on write (`:150-151`), so a
comment `tagio` preserved under the RFC bound would vanish from
mediafile's read of the same file with no error anywhere. `tagio`
validates to the RFC bound and records the divergence in the deviation
note ruling 1 produces, because the RFC is the format and mutagen is one
implementation of it.

**PICTURE** is big-endian throughout, unlike VORBIS_COMMENT, and more
than one block is allowed (section 8.8).

**PADDING** contents are zero bits, and more than one block is allowed
(section 8.3). SEEKTABLE is capped at one (section 8.5).

## What the writer guarantees

Each contract below is stated as behavior, with the proof that holds it
named. The proofs are the pass exit gates' content.

**What the conformance instrument can and cannot see, first, because it
bounds every proof below.** The ledger stores mediafile's read-back
VALUES rather than the comment set: `derive_file_tags.py:154` is
`values = {field: getattr(mf, field) for field in writable}`, and
`corpus/README.md:2398-2400` states the proof shape the same way. So the
instrument grades what a reader projects and proves nothing about which
bytes reached the disk. Two defect classes fall in that blind spot, and
each carries its own proof rather than riding the instrument. A writer
that emitted the vendor length, the comment count, or the per-comment
lengths big-endian would read its own files back correctly and agree
with all twelve subjects on all 69 keys. A writer that emits only
`ALBUMARTIST` and skips `ALBUM ARTIST` and `ALBUM_ARTIST` would do the
same, because both mediafile and `tagio` take the first truthy style,
and a file that passes every gate is then under-tagged for every
consumer but `tagio`, since Navidrome and others look for `DISCTOTAL`
and `TOTALDISCS`.

**The emitted bytes match the oracle's.** One small FLAC written by the
pinned oracle is committed to `internal/engine/tagio/testdata`, carrying
a VORBIS_COMMENT block and a PICTURE block, generated once under the
venv the way `template.flac` was. Proof: the writer's emitted
VORBIS_COMMENT and PICTURE block bytes equal the golden's for the same
input, the reader parses the golden, and the emitted comment set for
INV's measured fifteen-field write (`INV:409-427`) is asserted key by
key. `go-conventions` permits a golden at a high-fidelity surface whose
value is the literal bytes, which is this one.

**Read-back agreement.** For every one of the 69 writable keys, writing
a value through `tagio` and reading it back through `tagio` yields what
mediafile 0.17.0 read back from the same write. Proof: the conformance
instrument over the twelve ledger subjects, all 69 keys per subject,
plus the unit tests of ruling 1 for the sixteen the ledger leaves empty
and for the cases the twelve subjects never reach.

**Every block the writer does not own survives, and so does every
comment.** STREAMINFO's payload is copied byte for byte. SEEKTABLE,
APPLICATION, CUESHEET, and every reserved type are copied through by
declared length, in their original order, under re-emitted headers.
Inside VORBIS_COMMENT, a write replaces only the keys the tag set owns
and leaves every other comment in place and in order. Proof: a
round-trip test over a fixture carrying one block of each type,
asserting byte equality of every preserved payload; a test that a
reserved type the writer has never seen survives; and a fixture whose
comment block carries a foreign key, asserted intact after a write.

**Padding is exactly one block of 8 KiB.** The writer drops every
existing PADDING block and emits one 8 KiB PADDING block as the last
metadata block (rulings 5 and 6), so a file retagged N times carries the
same padding as a file retagged once. RFC 9639 section 8.3 permits more
than one padding block, so an append-and-keep writer would grow the file
8 KiB per retag, and rung 9's retag verb runs repeatedly over the same
library file. The oracle resizes rather than appending: measured, a
mediafile save into the 42-byte template produced STREAMINFO,
VORBIS_COMMENT, and exactly one 1024-byte PADDING block. Proof: the
block-chain assertion reads "exactly one PADDING block, 8 KiB, last",
which is also what catches a mis-set last-block flag, since a reader
that stops early never reaches the appended block.

The audio is untouched. The frame region is copied byte for byte, and
STREAMINFO's MD5 field is never recomputed. Proof: hash the frame region
before and after a write and assert equality, on a fixture carrying real
frames rather than the 42-byte template alone.

**A tag write is atomic or it does not happen, and it preserves the
target's mode.** The write goes through the new streaming path in
`internal/atomicfile`: a temp file in the target's own directory, the
new head, the copied frame region, sync, close, chmod to the mode the
caller passed, rename, then an fsync of the directory. A crash leaves
the old file intact. The mode is a parameter because `os.CreateTemp`
creates 0600, and rung 9 passes the target's existing mode by
stat-before-write. Proof: `atomicfile`'s existing test shape, extended
to the streaming function, including the assertion that a failed write
leaves the old content intact and leaves no temp file behind, and the
assertion that the renamed file carries the passed mode.

**A malformed container is refused, never half-written.** A second
VORBIS_COMMENT block, a STREAMINFO that is not first or not 34 bytes, a
block following a header whose last-block flag is set, a declared length
running past the end, or a field name outside RFC 9639 section 8.6's set
is an error, and the target file is not opened for writing. Proof: one
table-driven test per refusal, each fixture mutating one byte or one
length from a valid container.

Multi-value and date encodings match the oracle. A list writes one
comment per value under every writable style, and an empty list writes
none. A date writes the components the truthiness rule allows, with the
four-digit year, and its unpadded year fallback. Proof: the conformance
instrument covers both on real subjects, and the unit tests cover the
component combinations the twelve subjects do not reach, the zero year
among them.

**The tag set's write order is deterministic.** The three colliding
pairs resolve the way `sorted_fields()` resolves them, with the plural
winning. Proof: a test writing both members of each pair in one call
and asserting the surviving comments, which is the measurement
`INV:306-308` records against pinned mediafile.

## PICTURE

Owner ruling 3 puts the front cover inside launch scope. The corpus
grades none of it: `images` and `art` are `MediaFile` fields and are
not beets `Item` fields, so neither is in the writable 69
(`INV:432-441`). This work carries its own evidence.

What the reference does, and what `tagio` reproduces:

- A store replaces. mediafile's FLAC image style clears every picture
  and then adds each one, so a write replaces the whole set. Delete
  clears every picture, which is owner ruling 3's strip.
- The MIME type comes from sniffing the bytes. mediafile calls
  `filetype.guess_mime(data)`, and `tagio` sniffs by magic bytes
  in-repo, which is also CN's recommendation for container detection.
- The picture type is the ID3v2 APIC enumeration, 0 through 20, with
  front cover at 3. An unset type is 0, and an out-of-range index
  degrades to `other`.
- Front-cover selection, when several pictures exist, takes the single
  candidate when there is one, then the first with type front, then the
  first of any type.
- A write emits zero for width, height, colour depth, and
  indexed-colour count, and a rewrite discards whatever geometry the
  incoming picture carried. mediafile's FLAC image write builds a fresh
  `mutagen.flac.Picture` and sets only data, type, mime, and desc
  (`mediafile/storage/flac.py:30-37`), and `Picture.__init__`
  initialises all four to 0 (`mutagen/flac.py:577-586`). Revision 1 said
  the fields stay at the reference's values, which reads as
  preserve-on-round-trip and would diverge from the oracle on any real
  file whose cover block has real dimensions. A Go writer that fills
  them from a decoded image also writes more than the reference did.
  Rung 8 does neither, and the rung's close records the choice, so a
  later rung that wants real dimensions changes a stated behavior rather
  than discovering an accident.

Proof: a round-trip test over a small fixture image, asserting the
sniffed MIME type, the type index, the replacement semantics, the strip
path, and geometry equal to zero after a write. The golden container
carries a PICTURE block, so the emitted bytes are graded against the
oracle's as well.

This lands `S2`'s hook 3, whose art blob at admit depends on embedded
pictures being extractable once rather than at serve time
(`S2:363-364`).

## The package and its types

`internal/engine/tagio`, the leaf the tree shape already reserves
(`BS:330`, `BS:348`: `tagio` is FLAC file I/O unrelated to the tagging
flow born in 3d). Types are stated as contracts. The plan specifies
outcomes, and the implementer writes the code.

**Package invariants, all three enforced by tests that already exist.**

- `internal/engine` may not import `internal/harness`
  (`internal/harness/conform/arch_test.go:141`). The walk covers every
  `.go` file outside a `testdata` subtree, **including test files**, so
  the conformance instrument decodes `corpus/analysis/file_tags.json`
  into its own local types and never reaches for
  `internal/harness/analysis`.
- `internal/engine` may not call `time.Now`
  (`arch_test.go:152`, walking nested packages). A tag write stamps
  nothing, so this costs `tagio` nothing.
- `tagio` does not import `internal/engine/matcher` (ruling 3).

**The tag set.** A named type carrying the 69 writable fields with
their Go-native types, where each field is in one of four states: a
value, an empty string, an empty list, or absent. The state distinction
is the type's reason to exist, because `MediaFile.update`'s
delete-on-null rule makes it load-bearing on twenty keys per ledger row,
and because the two empty forms serialize differently. A string field's
zero value and a list field's zero value are the same in Go and are not
the same on disk, so the type carries the presence bit rather than
inferring it. Iteration over the set for a write is in a fixed order
that resolves the three colliding pairs the way `sorted_fields()` does.
The set is `tagio`'s own vocabulary, and no consumer's type appears in
its signature.

**The container.** A parsed FLAC file: the block chain in order, each
block carrying its type, its declared length, and its payload;
STREAMINFO decoded; VORBIS_COMMENT decoded to its vendor string and its
comments with repeats and order preserved, which the shadow's
`map[string]string` cannot hold; PICTURE decoded; and the offset and
length of the frame region, which is what ruling 8's hashable extent
names.

**The picture.** Data, type index, MIME type sniffed from the data, and
description. Geometry fields are carried on read and written as zero,
which is what the reference does.

**The two entry points a caller uses.** One reads a file's tag set and
its pictures, projecting all 69 keys with first-truthy-style precedence,
the last-style rule for a non-truthy read, the `safe_cast` behavior, the
date tuple, and the Q-number division. One writes a tag set and its
pictures over a file, atomically, preserving everything it does not own.
Both land in pass 8a; the read projection is the largest single item in
that pass, and putting it there is what makes 8a's read-back agreement
guarantee provable inside 8a. The conformance instrument calls the
exported reader rather than carrying a second projection, because two
decoders over one field bag drift silently. Rung 9 needs exactly these
two, over one file, in all three of its call shapes: write on admit,
retag in place, and move, which touches no tag at all
(`INV:938-954`).

**Erratum, 2026-09-08 (pass 8b's close, R12).** "One reads a file's tag
set and its pictures" is corrected: pass 8b ruled that `Read`
(`internal/engine/tagio/read.go:17`) stays tag-only, and the picture
read is reached through `Parse`'s `Container.Pictures`, never through
a combined entry point. A caller wanting both parses the file twice.
This is a stated deviation and a declared coverage gap, not a defect;
the combined shape is handed to rung 9, the first caller in a position
to pick between a second exported read entry point and an exported
projection over a parsed `Container`.

**Errors** are sentinels where a caller branches. Rung 7's gate
branches on "this container is not supported", and rung 9's repair
verbs branch on "this file is malformed". Those two are sentinels; the
rest are wrapped context.

## The per-format seam

Ruling 1 requires the seam. CN adds its shape: dispatch by container to
a tag-standard implementation, because five tag standards cover
fourteen containers, and pinned mediafile is organized the same way
(`mediafile/storage/` holds exactly `flac.py`, `mp3.py`, `mp4.py`,
`vorbis.py`, `ape.py`, and `afs.py`).

**The shape at rung 8: a registry keyed by container, with one entry
and no interface at all.** The go-conventions rule is about existence
rather than export, so an unexported single-implementation interface is
the same anti-pattern as an exported one. The registry's value is a func
value, which is what keeps a map of one entry from becoming a type
hierarchy. What rung 8 exposes is the supported set and a dispatch that
sniffs the container from magic bytes and routes to the FLAC
implementation or returns the unsupported-container sentinel. The MP3
pass adds the second implementation and the interface at the same time,
which is one refactor inside `tagio` rather than a change at every call
site.

**Rung 7 reads its allowlist bound from the seam.** `BS:630-638` states
that the intake allowlist is bounded by rung 8's support. Reading that
bound from the registry rather than restating it as a config default is
what makes a later container a registration rather than an edit in two
places. Rung 8 exposes the supported set for that purpose and consumes
nothing from rung 7.

**Per-format reject wording is rung 7's**, in the string authority,
naming the format. Rung 8's contribution is the sentinel and the
container name the wording needs.

Hook 13's sort tags are one more argument for dispatching by tag
standard: the FLAC and Ogg names are `ALBUMARTISTSORT` and `ARTISTSORT`,
the MP3 frames are `TSO2` and `TSOP`, and the MP4 atoms are `soaa` and
`soar` (CN, "Forward hooks 13 and 14").

## The write path

**Full rewrite only at launch** (ruling 5). Open a temp file in the
target's directory, write the signature and the new metadata blocks,
copy the frame region with `io.Copy`, sync, close, chmod to the caller's
mode, rename, fsync the directory. Cost is one full file copy and one
file's worth of free space. Safe under a crash.

`internal/atomicfile` grows a streaming write (ruling 11). Its only
exported function takes `[]byte`
(`internal/atomicfile/atomicfile.go:15`), so a multi-gigabyte FLAC
rewrite through it buffers the whole file. That is the same defect
`go-flac`'s v1 `Save` carries, and shipping it would be worse, because
the estate's library is where multi-gigabyte files live. `S2`'s
prior-art table already commits to extending `atomicfile` rather than
inventing a second temp-file convention, which makes the extension rung
8's work rather than a later rung's.

**The new function fsyncs the containing directory** (ruling 12), takes
the mode as a parameter, and leaves `WriteFile` alone. The shadow's
small JSON records need neither. A library file needs both, because a
renamed 0600 temp file is unreadable to the streaming service that runs
as another user, and the audio bytes underneath it are perfect, so no
integrity check would notice.

**Exactly one PADDING block of 8 KiB, last, on every write** (rulings 5
and 6). Every existing PADDING block is dropped. The in-place path stays
available and unbuilt. The trigger to build it is a measurement showing
the copy cost matters, named here so a later rung takes a decision
rather than discovering an option.

The frame region's offsets are exposed (ruling 8's mechanism). The parse
already computes them, and exposing them costs nothing.

## The conformance instrument

The instrument lives under `internal/engine/tagio` with its own
`testdata`, read-only against `corpus/` and `internal/harness`, which
is the ownership row `RE` cell (8,3) already wrote. It pins no schema
version of its own and never calls `Reconcile`.

It reads fourteen tracked files: the ledger, the template, and the
twelve `corpus/cases/<id>/case.json` files that hold the applied fields.
The ledger's rows carry only `case_id`, `item_index`, and `values`, so
the case files are where step 2's input lives. All twelve subjects'
applied fields cover all 69 writable keys, verified, which is what makes
step 2 viable at all: the shim builds a fresh `Item` from those fields
and calls `Item.write`, and because the applied fields already carry
beets' defaults for every unsupplied key, nothing falls back to a
default the Go side would have to guess.

Five steps, matching what `derive_file_tags.py` did, in the same order
(`INV:563-591`):

1. Copy the committed 42-byte template
   (`internal/harness/oracle/testdata/template.flac`) to a scratch path
   per subject. Never write into `corpus/` or `internal/harness/`.
2. Take the subject's frozen `Expected.AppliedFields` from the
   committed case, filtered to the ledger's own `writable_fields`
   header. Read that header rather than hardcoding a second list, which
   is the rule the shim follows.
3. Write those values with the four-state rule.
4. Read the container back through `tagio`'s own reader, and project
   each of the 69 keys to the ledger's JSON shape, including the
   four-state distinction, the last-style rule for a non-truthy read,
   the int and float casts, the list shape, and the date decomposition.
5. Compare against the row. The nine read-only keys are never compared
   per subject. The `template` block describes the fixture and no case.

The read-back projection is the part that is easy to underestimate. It
is a full reimplementation of `MediaField.__get__` for the 69 fields,
including first-truthy-style precedence, the last-style fallback,
`safe_cast`, the date tuple, and the Q-number division. It belongs to
pass 8a as the package's exported read entry point rather than to the
instrument, so that one projection serves the instrument, rung 9, and
the shadow. The shadow's reader already does it for eighteen rows and is
the nucleus.

**Where a disagreement goes** (ruling 2). A divergence between the Go
writer and the ledger is first a bug in the Go writer. When it survives
investigation and the resolution is an owner question, it becomes a
divergence record beside the conformance run, routed into
`corpus/analysis/adjudications.json` as a schema addition through the
same path rung 4 uses, never by hand-editing a derived record. An
unadjudicated divergence blocks the launch gate the same way a shadow
divergence does.

**The gate gains nothing.** `internal/engine/tagio` is Go under
`./...`, so `make check` already covers it. One shape is declined: a
conformance run that shells out to the venv, because the gate never
requires uv or beets by design. Revision 1 also declined a new binary
fixture on the ground that the instrument reads only tracked files. That
decline is narrowed to a second conformance corpus. One golden container
is committed, because it is the rung's only anchor to bytes another
implementation produced, and the instrument reading tracked files is an
argument about the instrument rather than about the writer.

## Risks

**1. A value model that is subtly wrong on many keys at once.** The
four-state rule and the write-every-style rule each fail this way: one
misreading produces twenty wrong keys per row rather than one.
Mitigation: the pass split puts the grading in its own pass with its
own review, the instrument grades all 69 keys on all twelve subjects,
and 8b's exit gate includes a proof that the instrument can fail.

**2. The sixteen ledger-silent keys ship unproven.** They carry the
float formatting, the suffix, and the Q8 shift, which is the trickiest
quarter of the surface. Mitigation: ruling 1's unit tests, one per
serialization rule, each citing its mediafile line, with hard-coded
expectations rather than expectations derived from the code under test.
The close records the deviation note so rung 15 reads a statement.

**2b. A defect the conformance instrument cannot see by construction.**
The ledger stores read-back values, so a wrong endianness or a skipped
style agrees with all twelve subjects on all 69 keys and ships a library
no other player reads correctly. Mitigation: the golden container and
its byte assertions, and the emitted comment set graded key by key
against INV's measured write. Both are 8a exit-gate content rather than
8b's, because a writer that reaches 8b with wrong bytes has already
passed the pass that was supposed to catch it.

**3. A tag write damages audio.** This is the failure that makes a tag
writer unusable, and it is what `go-flac` v2's `saveInPlace` risks and
what re-encoding through `mewkiz/flac` guarantees. Mitigation: the
frame region is copied byte for byte, STREAMINFO's payload is copied
byte for byte, the MD5 is never recomputed, and the exit gate hashes
the frame region before and after.

**4. A crash during a write.** Mitigation: full rewrite only at launch,

## Process

Each pass gets its own plan via writing-plans, drafted just in time in
the shadow of the previous pass's execution and never front-loaded.
Plans carry a token ceiling and a checkpoint interval, and state per
task whether it lands a 2.0 hook or is neutral. Execution runs the
implementer, `diff-reviewer`, gate chain per task, with workflow mode
at six or more tasks. The gate is `bash scripts/check.sh`, green at
every task end, never commit red, specific files only. Both budgets are
scored at every pass close.

`go-conventions` before any Go. No `vps-conventions` work exists in this
rung, because it touches no unit, no deploy path, and no box surface.
Subagents cannot dispatch agents, so the conductor owns the
`code-simplifier` dispatch at each pass close.

**Review scales to rung risk.** Rung 8 is not one of the three
full-adversarial-cycle rungs; auth (5), streamer and SSO (12), and
cutover (16) keep that. Rung 8 rides the in-chain `diff-reviewer` per
task plus the pass-end gate. The conformance run is the exit gate, and
8b's requirement that the instrument be shown able to fail is the
assertion-discipline rule applied to the one test that could otherwise
grade nothing and stay green. The golden container's byte assertions sit
beside it at 8a for the defects the conformance run cannot see.

**Owner touchpoints rung 8 expects, and only these.** Product fork B,
asked once before 8a's plan is drafted. Revision 1 expected two
questions; the content-hash question is ruled here as ruling 8, so one
remains. Any divergence that survives investigation and needs an owner
adjudication joins the standing adjudication stream rather than opening
a new one.

## Universality

Nothing in this rung is site-specific. The writer implements a
published format and a pinned library's serialization, both of which
are the same for every adopter. The conformance target is the committed
corpus, which carries no estate path or identity. The rung declares no
configuration key, so there is no default to get wrong for a stranger.
The one estate-shaped fact nearby, that the group's library is
FLAC-only, is rung 7's allowlist and rung 7's config, bounded by what
this rung supports rather than by what this estate holds.

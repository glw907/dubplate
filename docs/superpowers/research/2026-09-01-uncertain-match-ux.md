# Uncertain-Match Handling in Shared Music Servers: Research Report

## Synthesis and recommendation

Across every comparable tool surveyed, no widely-used system lets a non-admin, non-expert contributor resolve an ambiguous match in a genuinely multi-user, shared-trust context. The tools that offer a real interactive candidate picker — Lidarr, Roon, Picard — are single-admin or single-owner software with no contributor-role concept at all; "who decides" doesn't arise because there is only ever one decider. Plex is the one directly-evidenced multi-user case, and it resolves the question by locking match-correction to the server admin: a Plex staff moderator states flatly that "'Fix Match' is an administrative task and as such is only allowed for the server admin," with the only workaround being to hand over the admin PIN ([forums.plex.tv](https://forums.plex.tv/t/can-i-allow-users-the-ability-to-fix-match/483900)). Jellyfin has per-library user permissions but no granular metadata-edit permission bit — unprivileged users can't even edit metadata on content they own ([jellyfin.org docs](https://jellyfin.org/docs/general/server/users/adding-managing-users/), [jellyfin-web#5641](https://github.com/jellyfin/jellyfin-web/issues/5641)). Funkwhale is the outlier with genuine contributor self-service, but it sidesteps confidence-matching entirely: no automated matcher runs at all, each user's uploads live in their own library with an independent visibility scope, and the uploader freely edits their own track metadata after the fact ([libraries](https://docs.funkwhale.audio/user/libraries/index.html), [edit metadata](https://docs.funkwhale.audio/user/libraries/content/edit.html)).

That pattern gives four defensible points on the spectrum:

**A. Contributor picks from the matcher's own top-N shortlist.** Who decides: the contributor, bounded to candidates the matcher already surfaced (no open search). Validated loosely by Lidarr's popularity, but only in single-admin deployments — no tool extends this to a lesser-privileged multi-user role. Risk: non-experts pick wrong, especially in weak-coverage genres where the "right" answer may not even be in the top N.

**B. Contributor confirms one single low-confidence candidate (yes/no).** Lower cognitive load than a full picker, still contributor-decided. No direct precedent in any surveyed tool — it's a hypothetical lighter-weight cut of Lidarr's flow. Risk: rubber-stamping; a yes/no gate is easy to click through without real scrutiny.

**C. Everything uncertain routes to an owner decision queue.** Directly validated by Plex's admin-only Fix Match and reinforced by the Overseerr/Ombi request-gating pattern common in shared *arr stacks, where an approval layer sits between "user wants X" and "X lands in the library." Satisfies the "don't let contributors wreck the library" need. Risk: makes the owner a standing bottleneck, working against dubplate's own "ease of setup, no site-specific dependency on one person" goal, and doesn't scale for an unattended family server.

**D. Refusal with the private-collection escape hatch (current dubplate behavior).** Structurally close to Funkwhale's design (trust the uploader's own tags, scoped away from the main matched library) and philosophically aligned with Navidrome's own stance — a Navidrome contributor explains the maintainer's position that the app has deliberate read-only access to the music directory, partly for security, so tag correction happens upstream, not in-app ([discussion #2418](https://github.com/navidrome/navidrome/discussions/2418); community workaround is external sidecar files, not editing — [discussion #3181](https://github.com/navidrome/navidrome/discussions/3181)). It's also validated by MusicBrainz's own guidance to add missing bootleg/live releases to MB itself rather than force a match ([Style/Live_bootlegs](https://musicbrainz.org/doc/Style/Specific_types_of_releases/Live_bootlegs)). Gap: it doesn't distinguish "sloppy tagging" from "correctly tagged material MusicBrainz simply covers poorly" — classical, compilations, and box sets are the clearest evidence of this gap (see below), and refusal demotes legitimately good contributions to a second-class collection rather than the main library.

The strongest actionable finding is that gap in Option D: classical/compilation material is a *structural* weak point for MB matching, not a tagging-quality problem, so refusal-plus-private-collection may be systematically unfair to a whole genre of honest contributions even though no comparable tool offers a better multi-user alternative to copy.

## Per-tool survey

- **Lidarr** — Interactive Manual Import picker on failed match, but no per-user roles at all; complaints target picker tedium at scale ([#944](https://github.com/lidarr/Lidarr/issues/944), [#5645](https://github.com/Lidarr/Lidarr/issues/5645)), and multi-user support itself is an open, unresolved ask ([Sonarr#1682](https://github.com/Sonarr/Sonarr/issues/1682)).
- **Plex** — "Fix Match" is admin-only by explicit policy ([support.plex.tv](https://support.plex.tv/articles/201018497-fix-match-match/), [forum confirmation](https://forums.plex.tv/t/can-i-allow-users-the-ability-to-fix-match/483900)).
- **Jellyfin** — Per-library user permissions exist; no granular metadata-edit permission distinct from admin rights ([docs](https://jellyfin.org/docs/general/server/users/adding-managing-users/)).
- **Funkwhale** — No automated confidence matching; per-user libraries with visibility levels, full self-service metadata editing on one's own uploads ([libraries](https://docs.funkwhale.audio/user/libraries/index.html)); an early ask for editable metadata ([issue #504](https://dev.funkwhale.audio/funkwhale/funkwhale/-/issues/504)) evolved toward a suggest-edit-plus-permissioned-review model.
- **Roon** — Single-owner "Identify Album" dialog on unidentified albums ([help.roonlabs.com](https://help.roonlabs.com/portal/en/kb/articles/identifying-albums)); no multi-user concept.
- **MusicBrainz Picard** — Gold-standard interactive matcher, single local user, color-coded similarity scoring ([workflow docs](https://picard-docs.musicbrainz.org/en/latest/workflows/workflow_album.html)).
- **beets** — CLI prompt (choose candidate / more candidates / as-is / skip / manual search) ([tagger guide](https://beets.readthedocs.io/en/stable/guides/tagger.html)); its web/aura plugins multiplex endpoints, not multi-user permissions.
- **Ampache/Koel/Airsonic** — Tag-following, source-preference ranking at most ([Ampache FAQ](https://ampache.org/docs/help/troubleshooting/faq/)); no matching/confidence UI found for Koel or Airsonic.
- **Navidrome** — Files-are-truth by deliberate design, no in-app metadata editor ([discussion #2418](https://github.com/navidrome/navidrome/discussions/2418)).

## User-needs evidence

- **"Let me pick"**: Lidarr's picker is wanted, not resented — complaints are about bulk efficiency ([#5645](https://github.com/Lidarr/Lidarr/issues/5645), [#337](https://github.com/lidarr/Lidarr/issues/337)).
- **"Stop second-guessing my tags"**: Navidrome feature request cites Ampache as the alternative specifically for browser tag editing ([discussion #2418](https://github.com/navidrome/navidrome/discussions/2418)); maintainer-adjacent answer is "fix it upstream."
- **"Classical/compilations always mismatch"**: MetaBrainz Discourse documents MB's classical coverage gaps ([thread 1](https://community.metabrainz.org/t/problematic-tagging-for-classical-music/703557), [thread 2](https://community.metabrainz.org/t/musicbrainz-seems-to-know-very-little-classical-music/55935)); beets issues show structural false-negatives on classical/compilation releases even with explicit MBIDs ([#1665](https://github.com/beetbox/beets/issues/1665), [#6244](https://github.com/beetbox/beets/issues/6244), [#4882](https://github.com/beetbox/beets/issues/4882), [#6598](https://github.com/beetbox/beets/issues/6598)) — the strongest single finding here.
- **"No MB entry for bootlegs/unreleased"**: MB's own style guide expects submission to MB first ([Style/Live_bootlegs](https://musicbrainz.org/doc/Style/Specific_types_of_releases/Live_bootlegs)); community pattern otherwise is accept-as-singleton/manual import.
- **"Don't let contributors wreck the library"**: Plex's admin-only Fix Match is the clearest precedent ([forum](https://forums.plex.tv/t/can-i-allow-users-the-ability-to-fix-match/483900)); Overseerr/Ombi-style request-gating in the broader *arr ecosystem reinforces that shared-library operators default to not trusting arbitrary contributors with direct correction rights.
- **Funkwhale upload UX**: 2018 ask for editable metadata ([issue #504](https://dev.funkwhale.audio/funkwhale/funkwhale/-/issues/504)) shows demand for post-upload self-correction predates and shapes Funkwhale's current per-uploader editing model.
- **Plex non-owner access**: same forum thread confirms no managed-user delegation exists for match correction at all.

**Gap flagged**: direct Reddit evidence (r/selfhosted, r/PleX, r/musichoarder, r/lidarr) did not surface through the search tooling used; GitHub issues and vendor forums carried the evidentiary weight instead.

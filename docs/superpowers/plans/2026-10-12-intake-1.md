**Outcome.** A signed-in member sends a FLAC album, or a set of separate tracks, to the server over tus. The server
reserves space at creation, stages the bytes on the music volume, runs the gate over them, and records a verdict. A
passing album waits in `matching` for `intake-2`'s probe; separate tracks with a passing file land in "Unlisted
music" as `accepted`; a failing submission ends `rejected` with each file's reason in its contract wording. Every
state reads back through the `/api/v1` submission operations. Nothing is admitted to the library (`pipeline`), and no
page is built (`intake-2`).

**Pass class:** `auth-data`. It writes a migration, `internal/serve` tests, `cmd/dubplate-server`, and `systemd/`;
each task names its own class below. No task touches the box, a Cloudflare account, or a live mail server, so the
pass carries no `live-account` flag beyond the branch push and PR on `glw907/dubplate`.

**Out of scope.** As the design says: the match probe, the unlisted route's form and `route_unlisted`, the uploader
page, resume, and the landing (`intake-2`); the photo loader, the styled 404, and the sitting (`intake-3`); admission
and layout (`pipeline`). Spec acceptance criteria 12 (resume), 25 (the probe), 30 (pages, the landing, the styled
404), and 32 (the page) are not this pass's, nor are AC 23's two race clauses through `matching` and `route_unlisted`,
AC 26's `route_unlisted` column and its `pushed-back` and `match-unavailable` rows, and AC 27's `matching` half (the
fold verification read assigned that half and AC 25 to 7b), and AC 11's two clauses that need the real client
(a dropped response ending in the client's success, a lost 201 ending in an upload through `uploadUrl`), whose

## Conventions every task follows

- **Gate.** `bash scripts/gate.sh` (the full gate) and `bash scripts/gate.sh --scope-changed --base <base>` (the fast
  lane), from the worktree root, with the Bash tool's `timeout: 600000`, re-issued on exit 75 until it prints `gate
  exit:`. A worktree-isolated session's Bash guard refuses the quoted `cairn-run-gate '<string>'` form and accepts the
  wrapper. Never fall back to a bare `bash scripts/check.sh` for an acceptance.
- **The base, and why the fast lane names it.** `check.sh` classes `go.mod`, `go.sum`, `web/package.json`,
  `web/package-lock.json`, `scripts/check-state-dir.sh`, and `Makefile` as gate machinery (`check.sh`,
  `classify_path`, near `:364-370`), which promotes a scoped run to the full form. T0, T6, T9, and T12 write
  machinery files. Without `--base`, a branch's change set runs from the merge base with master, so every later scoped
  run would include them and run the full gate. Every fast lane on this branch therefore passes `--base <base>`, where
  `<base>` is the literal 40-hex id of the commit the task started from: the session's `HEAD` at task start, written
  into the clock file as a fourth line `base=<sha>` (the clock hook reads only `task=`, `start=`, and `estimate=`),
  or, for a pair or a single dispatch, the dispatch commit. `check.sh` uses a supplied base only when it is a full
  hex id that resolves to itself and is an ancestor of `HEAD`, and otherwise runs the full form, so a wrong value
  costs time, never coverage. A task that itself writes a machinery file runs the full form by that rule; that is
  expected. This departs on purpose from the adapter's "Pass no `--base`", as `admin-api-1` did (its PR's "Found, not
  done" item 17); a resumed session keeps it.
- **Setup.** `npm ci --prefix web` in the session's worktree, and in each subagent's worktree before its first gate
  (the gate refuses a worktree without `web/node_modules`).
- **Test-first.** Every `auth-data` task, and every task marked "written test-first", writes its acceptance tests
  first and records each failing at the task's start commit, in the PR notes, before the code lands.
- **Mutation proofs are run.** Each task's mutations are applied one at a time, the named test run, and the failure
  recorded in the PR notes with the test name. A mutation that does not fail is a finding against the test, fixed in
  the same task. No mutation is narrated in a comment.
- **Fixture states.** Every proof names the fixture state it needs (populated, selected, faulted, raced), so it
  cannot pass on an empty fixture. Every test that moves a submission between states ends by asserting that each
  `submissions.state` equals the `kind` of its latest state event by `seq` (T4; the spec's acceptance preamble;
  `stalled` is an event, not a state, so it never counts); T4 owns the helper and proves the assertion can fail.
  Every intake write stamps `at` from one injected clock, so a test that drives the sweep's clock drives every
  event's.
- **Layering.** `internal/intake/gate`, `internal/intake/staging`, and `internal/reject` import no
  `internal/engine/store` (AC 34's cross-compile means nothing otherwise). `internal/intake` imports no
  `internal/auth` and no `internal/notify`: `cmd/dubplate-server` injects the session verifier, the live-admin
  addresses, and the mail send. `internal/ops` and `internal/ops/opshttp` keep importing no `internal/auth` or
  `internal/settings` (the `admin-api-1` rule); `internal/intake` may import `internal/ops` and
  `internal/settings`. `internal/intake` never imports `internal/serve` (P8's in-package test imports `intake`), and
  `internal/intake/gate` imports no `internal/ops`: the seam maps the gate's manifest errors to details (P4).
  `github.com/tus/tusd/v2` is imported only by `internal/intake`; `pkg/filelocker` never.
- **No export ahead of a caller.** Every new export names its production caller in the task that adds it. The states
  this pass defines are the ones it emits (P5).
- **Config keys** are declared from this pass's own file, `cmd/dubplate-server/intake.go`, registered through one
  `newProductionRegistry` line (`cmd/dubplate-server/main.go:99-109`). `internal/config/keys.go` changes only by the
  two class removals (P2).
- **Skills.** Go under `go-conventions`, with "idiomatic, architecturally beautiful Go" an acceptance dimension of
  every Go task; Python none; `web/` is touched only by T0's one pin and T10's three `API_DETAILS` lines in
  `web/src/lib/copy/deck.ts` (the deck gate requires one per `Detail*` constant). Copy uses plain terms: "the
  group", "a member", "music" or "recording" where "album" would be wrong (spec owner ruling 1).
- **Per-task review.** On each `auth-data` task, on T8 (written as the `auth-data` write path it is), and on T7 (a
  hand-ported parser of member-supplied archives, which the adapter's path map does not class), the session
  runs `diff-reviewer` at task scope on the task's commit (or the merged pair's range) against the task's acceptance.
  `accept` continues. `fix` gets one fix commit whose acceptance quotes each finding verbatim (location, finding,
  fix), then one re-read. A second `fix`, or any `escalate`, is a stop. Each verdict, the re-read's included, appends
  `review T<n>=<verdict> <sha>` to the PR notes.
- **Commits.** One commit per task, subject starting with the task id (`T4: Add migration 0006 and the intake
  collections`), imperative mood, specific files only (`git add <path>...`, never `-A`), with the trailer the
  session's system reminder names. A pair half merges with `git merge --no-edit <branch>`.
- **Records.** The PR notes live at `<git dir>/pr-notes.md`, where `<git dir>` is `git rev-parse --absolute-git-dir`
  in the session's worktree: never committed, and they survive a restart. The first line, written right after the
  planning-branch merge, is `launch-base=<sha>`. Before each dispatch the session appends `dispatch T<a>[+T<b>]
  sha=<40-hex>`. Each task appends its test-first failures, its mutation results, its review line, its quoted
  behaviors (below), and anything found outside its scope. A subagent writes nothing outside its worktree and returns
  its records in its final report, with its worktree path and branch; the session appends them. The session writes
  with the Write tool or one plain command per write.
- **Clock.** At each task start the session writes `pass-task-clock` in its worktree's git dir with `task=<id>`,
  `start=<epoch>`, `estimate=<minutes>`, and `base=<sha>`, and removes it at the task's end. For a pair or a single
  dispatch it writes one file (`task=T2+T3`, the larger estimate, the dispatch commit as `base`) before dispatch,
  checks the overrun when the dispatch returns, then removes it. Subagent worktrees hold no clock file.
- **Dispatches.** A pair is two Agent-tool subagents, `subagent_type: "general-purpose"`, `isolation: "worktree"`,
  effort `medium`, dispatched after the session commits, so `worktree.baseRef: "head"` branches them from that
  commit. T8, T9, and T11 run on `opus` (novel correctness-critical logic the spec leaves to the implementer: the
  reservation and transition transactions, the tus wrapper's authorization, the startup pass and the worker's
  recovery); every other dispatch runs on `sonnet`. T11 is a single dispatch the session waits on. The dispatch names
  the commit's full id; the subagent's first act is `git merge-base --is-ancestor <dispatch sha> HEAD`, and a failure
  is a stop. Each gets its task's full text, the "Decisions this plan takes", "Behaviors this plan relies on,
  quoted", "States", and this section, all verbatim, plus the spec's path with the instruction to read every spec
  section and AC its task cites before writing tests; commits; never pushes; and skips agent-memory maintenance.
  Every dispatch carries pass-core's two over-engineering samples verbatim. The session merges, runs the fast lane
  with `--base <dispatch sha>`, runs the per-task review, and pushes.
- **Stops.** A red the session cannot fix in two attempts, a merge conflict, a clock stop, an auto-mode classifier
  refusal, a per-task review stop, or a finding that would change the approved design: write `docs/STATUS.md` on the
  branch (task in flight, what failed, one question with a recommendation), commit and push it, run `notify-send -u
  normal "intake-1: stopped"`, and wait. Never work around a refusal with another tool. A subagent whose gate is not
  green after two attempts returns its work uncommitted, and the session applies this rule before merging.
- **Resume.** After a crash, an API drop, or a restart, the session (the same one, or a fresh one launched with the
  same prompt, which enters the existing worktree with EnterWorktree's `path`; a `worktree-intake-1` branch with no
  worktree directory is a stop, per the prompt's first check) first rewrites the clock file's `start=` to now. If the
  PR notes carry no `launch-base` line, it checks `git merge-base --is-ancestor worktree-intake-1-plan HEAD`, merges
  the planning branch if that fails, and finishes the prompt's launch steps. It reads this pass's task commits with
  `git fetch origin`, then `git log --no-merges --format='%h %s' <launch base>..HEAD ^origin/master`, where `<launch
  base>` is the PR notes' first line. Only the last `dispatch` line in the PR notes can be unsettled, since the
  session merges and reviews each dispatch before the next. For that line it lists the candidate branches with `git
  worktree list --porcelain` (each entry's `branch refs/heads/...` line), drops its own branch `worktree-intake-1`,
  and keeps those where `git merge-base --is-ancestor <dispatch sha> <branch>` holds. Each candidate is one of three:
  - it carries its `T<n>:` commit (`git log --format=%s <dispatch sha>..<branch>`) and is an ancestor of `HEAD`:
    merged, done;
  - it carries its `T<n>:` commit and is not an ancestor of `HEAD`: merge it now, run the fast lane with `--base
    <dispatch sha>`, run the per-task review, and push;
  - it has no `T<n>:` commit: a stop, since its worktree may hold warm uncommitted work, unless the same session can
    resume that subagent with `SendMessage`.

  A committed reviewed task with no `review T<n>=` line (and T11 with no `security-read=` line) is the task in
  flight, at its review step. Otherwise the session resumes at the first task whose acceptance fails and never
  re-applies a committed task.
- **Scope.** A defect found outside a task goes to the PR body's "Found, not done" list.

## Decisions this plan takes

The spec and the design leave these to the plan. Each is method or architecture, decided on its evidence.

- **P1. Packages.** `internal/reject` holds the reason set (T2). `internal/intake/gate` is the gate core: the Go path
  validator, the manifest checks, the per-file and per-album checks, the separate-tracks verdicts, and the ZIP walk,
  header count, and extraction; it imports no `store` (T4, T6, T7). Its own opens, writes, and removals go through an
  `os.Root` on staging; `tagio`'s functions take a path (`Sniff`, `Parse`, and `Read` each open a path string), so
  the gate hands them `filepath.Join(<staging>, <server-minted name>)`, a name no member chooses.
  `internal/intake/staging` is the platform leaf (T5). `internal/intake` holds the store side (the submission and
  collection SQL over `*store.Tx`, the limits, the transitions, receipt, the accept transaction), the tus mount and
  its wrapper, the `ops.SubmissionSeam` implementation, the worker, the startup pass, and the sweep (T8 to T11). A
  separate `internal/ops/<pkg>` adapter would wrap one caller, so the seam's implementation lives in
  `internal/intake` (the admin seam got its own package because it joins `auth`, `settings`, and the notice; this
  one joins only `intake`).
- **P2. The staging wall row and its nesting check.** `cmd/dubplate-server/intake.go` registers
  `DUBPLATE_STAGING_DIR` with `AddWallRow` (description "the directory on the music volume where uploads stage before
  admission", mark `Sensitive`, a path), and `DUBPLATE_UPLOADS_DIR` and `DUBPLATE_TRIGGER_DIR` with `AddSuperseded`,
  each naming `DUBPLATE_STAGING_DIR` (the `rosterFileKey` precedent, `auth.go:121-129`, `:330`). `keys.go` loses the
